# Lumina Select v0.5 专业选片工作流与 UI 设计规格

**版本目标：** 将 v0.4 的可运行选片原型升级为可长期使用的本地专业选片工具，完成 Lightroom 交付闭环，并重构复核界面的信息架构与视觉质量。

**目标平台：** Windows 11，最低有效窗口尺寸 1280×720，主要设计基准 1440×900，兼容 125% 与 150% DPI。

**确认日期：** 2026-09-09

---

## 1. 产品边界

### 1.1 v0.5 目标

1. 保持照片全程本地处理，不增加云端上传、账户系统或遥测。
2. 只解决选片，不增加调色、滤镜、RAW 显影或修图能力。
3. 保留 Torch 标准版与 OpenCV 轻量版，两版使用相同的工作流和 UI。
4. 将自动分析结果转化为可解释、可撤销的人工选片决策。
5. 通过标准 XMP sidecar 将星级、颜色标签和保留状态交付到 Lightroom Classic。
6. 在不重写算法核心的前提下拆分现有单文件 Qt 界面，建立可维护的 UI 边界。
7. 消除第三方依赖许可描述与实际包许可证不一致的发布风险。

### 1.2 明确不做

- 不开发调色、预设、滤镜、皮肤修饰或生成式修图。
- 不直接读取或修改 Lightroom 的 `.lrcat` 数据库。
- 不建设云图库、同步服务、多人账号或移动端。
- 不自动删除、移动或覆盖用户原始照片。
- 不在 v0.5 引入 VLM、大语言模型或新的在线推理服务。
- 不在本版本重写为 Electron、Web、Flutter 或其他 UI 框架。
- 不把完整图库管理、自然语言搜索和人脸身份管理纳入 v0.5。

## 2. 目标用户与核心工作流

目标用户是需要处理数百到数千张婚礼、人像、活动、宠物或旅行照片的摄影师及高频摄影爱好者。

主流程固定为：

1. **导入：** 用户选择一次拍摄目录，应用扫描 JPEG、PNG 与支持的 RAW 文件。
2. **分析：** 应用以当前推理后端运行技术质量、人脸、场景、相似聚类和综合评分。
3. **复核：** 普通照片使用单张视图，相似组和待甄选组自动进入比较视图，用户完成星级、保留和排除决策。
4. **交付：** 用户预览最终数量，将已选原片与 XMP sidecar 导出到 Lightroom 交付目录，或显式选择在原片旁写入/合并 sidecar。

应用不得跳过复核直接删除文件。AI 的角色是排序、提示和减少比较范围，最终决定权始终属于用户。

## 3. 已确认的 UI 方向

### 3.1 整体形态

采用“引导式入口＋专业复核工作台”：

- 导入、分析和首次导出采用低密度分步页面。
- 复核阶段进入高效率专业工作台。
- 顶部始终展示“导入 → 分析 → 复核 → 导出到 LR”的流程状态。
- 用户可返回前一步，但返回不得清除已经完成的分析或人工决策。

### 3.2 视觉主题

采用中性炭黑与香槟金：

| Token | 建议值 | 用途 |
| --- | --- | --- |
| `window-bg` | `#111315` | 窗口主背景 |
| `panel-bg` | `#181B1E` | 左右面板 |
| `surface-bg` | `#1C1F22` | 工具栏、底栏 |
| `border` | `#303338` | 分隔线 |
| `text-primary` | `#DFE2E6` | 主文字 |
| `text-secondary` | `#9299A1` | 次要信息 |
| `accent` | `#D7AA5A` | 当前选择、AI 推荐、主操作 |
| `positive` | `#73C69A` | 通过项、保存成功 |
| `warning` | `#DFB970` | 待确认、分差接近 |
| `danger` | `#D46A6A` | 排除、错误 |

约束：

- 背景必须保持中性，避免影响照片色彩判断。
- 香槟金只用于当前选中项、推荐标识和主操作，不用于大面积装饰。
- 不使用霓虹发光、大面积渐变、玻璃拟态或纯装饰性卡片。
- 正文默认使用 Windows 可用的 Segoe UI / Microsoft YaHei UI 字体回退链。
- 基础间距使用 4、8、12、16、24 px 序列。

### 3.3 复核布局

复核工作台由五个固定区域组成：

1. **顶部流程栏：** 品牌、项目名、照片总数、流程阶段和保存状态。
2. **左侧筛选栏：** 全部照片、AI 精选、待确认、已排除、技术问题、星级筛选及各项计数。
3. **中央画布：** 单张或比较视图，是窗口中面积最大的区域。
4. **右侧全量技术面板：** 推荐结果、关键人脸、评分、EXIF、模型和性能信息。
5. **底部区域：** 胶片带、快捷键提示、组进度和“确认并进入下一组”操作。

左栏默认宽度 160–200 px，右栏默认宽度 260–320 px；两者允许拖动调整并在项目内记住宽度。中央画布不得因右栏内容增长而产生水平滚动。

### 3.4 智能双模式

- 不属于相似组的普通照片默认进入单张大图模式。
- 相似组、待甄选组和用户主动比较的照片默认进入比较模式。
- 比较模式突出显示当前候选，其余候选保持可点击且显示候选字母与得分。
- `Tab` 在单张和比较模式之间切换。
- 双击候选进入单张 100% 检查；再次双击或按 `Esc` 返回比较。
- A/B/C/D 选择候选，候选超过四张时继续支持鼠标选择和左右方向键。
- 用户在当前项目中手动选择的视图偏好应保持到项目关闭。

### 3.5 全量技术面板

右栏常驻展示以下分组，允许分组折叠，但首次进入默认全部展开：

1. **决策摘要**
   - 综合分；
   - 建议保留、待确认或建议排除；
   - 与组内第二名的分差；
   - 推荐置信说明。
2. **关键人脸**
   - 每个已检测人脸的局部裁剪；
   - 睁眼/闭眼状态；
   - 人脸局部清晰度；
   - 点击人脸后中央画布定位并放大对应区域。
3. **评分明细**
   - 清晰度、曝光、美学、人脸及最终综合分；
   - 显示 0–100 数值和横向刻度；
   - 鼠标悬停显示该指标的简短定义，不暴露难以理解的内部公式。
4. **拍摄信息**
   - 文件名、分辨率、格式；
   - 相机、镜头、焦距；
   - 快门、光圈、ISO；
   - 拍摄时间和文件路径。
5. **分析信息**
   - Torch 或 OpenCV 后端；
   - 实际模型/算法名称；
   - 场景与置信度；
   - 单张分析耗时；
   - 模型签名和应用版本。

技术面板的数据必须来自数据库中的实际分析结果；缺失值显示“未提供”或“未检测”，不得用零值冒充结果。

## 4. Lightroom 与 XMP 交付

### 4.1 默认交付模式

“导出到 Lightroom”默认执行：

1. 用户选择一个新的或空的交付目录。
2. 应用复制被保留的原始资产，不改变源文件。
3. 为每个导出资产生成同名 `.xmp` sidecar。
4. XMP 至少写入：
   - `xmp:Rating`：0–5 星；
   - `xmp:Label`：Green / Yellow / Red；
   - `dc:subject`：可选的 Lumina Select 标签；
   - 自有命名空间中的分析版本和建议原因。
5. 导出结束后显示成功、跳过和失败数量，并提供打开交付目录按钮。

颜色映射固定为：

| Lumina 状态 | XMP 星级 | XMP Label |
| --- | ---: | --- |
| 用户明确保留 | 保留当前星级；无星时写 5 | Green |
| AI 精选但未人工确认 | 当前推荐星级 | Yellow |
| 用户明确排除 | 0 | Red |
| 未处理 | 不导出或不写入状态 | 空 |

### 4.2 原地 sidecar 模式

高级选项允许把 XMP 写在源文件旁，默认关闭，并满足：

- 不修改 RAW/JPEG 像素数据。
- 写入前展示受影响文件数量与目标路径。
- 已存在 sidecar 时只合并 Lumina 管理的字段，保留 Lightroom 调整、裁切、蒙版和其他命名空间。
- 合并前在应用数据目录创建可恢复备份。
- 任一文件失败不影响其他文件，最终报告逐项错误。
- 不提供直接修改 `.lrcat` 的选项。

### 4.3 RAW+JPEG 配对

- 同目录、同基础文件名且拍摄时间接近的 RAW 与 JPEG 视为一个资产组。
- 分析优先使用 RAW 内嵌预览或配对 JPEG，避免为选片完整显影 RAW。
- 用户对资产组的星级与保留决策同步应用于 RAW 与配对 JPEG。
- 导出时允许用户选择“仅 RAW”“RAW+JPEG”或“仅 JPEG”；默认 RAW+JPEG。
- RAW+JPEG 配对不得进入“高度重复”废片计数。

## 5. 软件架构要求

### 5.1 保留的技术基础

- Python 3.12；
- PyQt6 6.8；
- SQLite WAL；
- Pillow、OpenCV、MediaPipe；
- 现有 `InferenceBackend` 接口；
- PyInstaller onedir 与 Inno Setup；
- pytest。

v0.5 不改变双版本的产品边界：

- 标准版：Torch 后端，允许本地模型下载和 GPU 推理；
- 轻量版：OpenCV 启发式后端，无 Torch、无模型下载。

### 5.2 UI 边界

现有 `app_qt.py` 仅保留应用启动、主窗口组装和全局异常处理。新增 UI 按责任拆分：

```text
ui/
  theme.py             设计 token、QSS 加载与 DPI 适配
  main_window.py       顶部流程栏、页面导航、全局状态
  pages/
    import_page.py     导入与项目摘要
    analyze_page.py    分阶段进度、取消和错误恢复
    review_page.py     复核工作台组装
    export_page.py     Lightroom 交付预览与结果
  review/
    canvas.py          单张/比较画布与缩放
    filmstrip.py       虚拟化胶片带
    filters.py         左侧筛选与计数
    inspector.py       全量技术面板
    face_strip.py      关键人脸裁剪与定位
    shortcuts.py       快捷键映射
```

UI 不得直接拼接 SQL。所有查询和写入通过 `PhotoStore` 或明确的服务接口完成。

### 5.3 服务边界

```text
services/
  asset_pairing.py     RAW+JPEG 配对与导出资产选择
  xmp_service.py       XMP 读取、合并、备份、校验和写入
  export_service.py    复制资产、生成 sidecar、汇总结果
  review_service.py    复核队列、筛选、撤销与导航
```

- XMP 服务不依赖 Qt，必须可独立单元测试。
- 导出服务通过事件/回调报告进度，不直接操作 UI 控件。
- 复核服务负责状态变更和撤销，UI 只发出用户意图。
- 所有写文件操作先写临时文件，再以原子替换完成。

### 5.4 数据库

新增明确的 schema 版本及顺序迁移，不再只依靠静默 `ALTER TABLE`：

- 资产配对 ID 与角色；
- 每项评分的实际模型名和耗时；
- 人脸局部框、眼睛状态与局部清晰度；
- 人工决策来源和更新时间；
- XMP 导出状态、目标路径、错误摘要；
- UI 项目偏好，如左右栏宽度和最后视图模式。

旧 v0.4 数据库升级失败时保留原库并提示用户选择重试或重建，不得静默清空。

## 6. 依赖和许可要求

当前环境中的 `pyiqa 0.1.16` 使用 PolyForm Noncommercial 许可证，而项目 NOTICE 仍将其描述为 Apache-2.0。v0.5 发布必须满足：

1. `requirements.txt` 不得用宽范围自动引入许可证变化的包。
2. 标准版商业分发不得包含未取得商业授权的 `pyiqa` 代码或受限权重。
3. 若在模型替换完成前构建测试包，必须清晰标记为非商业评估构建。
4. `NOTICE.md` 必须依据实际锁定版本、打包内容和模型权重更新。
5. 构建流程生成第三方依赖清单并在安装包内提供。
6. 模型替代方案必须通过真实照片基准后才能替换现有评分口径。

许可证合规是发布门槛，不得以测试通过代替许可确认。

## 7. 错误处理与数据安全

- 导入失败必须区分不支持格式、文件损坏、权限不足和解码失败。
- 分析取消后保留已完成结果，并允许继续。
- 模型加载失败应明确显示当前降级后端及受影响能力。
- 缩略图和预览损坏不得阻止其他照片复核。
- XMP 合并失败不得覆盖原 sidecar。
- 导出目标空间不足时在复制前预警，在失败后保留可重试清单。
- 界面关闭前若有未完成写入任务，应提示等待或安全取消。
- 日志不得包含照片内容、用户隐私元数据或完整 XMP 正文。

## 8. 性能要求

在 README 所述 RTX 4060 基准机上：

- 1000 张已完成分析的项目进入复核页不超过 3 秒。
- 左侧筛选切换后首屏更新不超过 300 ms。
- 胶片带滚动过程中不一次性创建全部缩略图控件。
- 比较模式最多同时解码 5 张高分辨率预览。
- 100% 查看按需加载，离开照片后允许释放大图内存。
- UI 主线程不得执行模型推理、RAW 解码、批量复制或 XMP 写入。
- 轻量版和标准版使用同一 UI 性能验收标准。

## 9. 可访问性与交互要求

- 所有主操作支持键盘完成。
- 当前焦点、当前候选和 AI 推荐使用不同的视觉状态，不只依赖颜色区分。
- 文字与背景保持可读对比度。
- 125%/150% DPI 下按钮和文字不得截断。
- `P` 保留、`X` 排除、`0–5` 星级、`A/B/C/D` 候选、方向键导航保持兼容。
- 新增 `Tab` 单张/比较切换、`F` 全屏、`I` 显示/隐藏技术面板。
- 所有破坏性或批量覆盖动作必须有范围预览和二次确认。

## 10. 测试与验收

### 10.1 自动化

- UI 纯逻辑使用 pytest 单元测试，不依赖真实窗口。
- 关键 Qt 交互使用 `pytest-qt`：
  - 视图自动切换；
  - 快捷键；
  - 筛选计数；
  - 撤销；
  - 技术面板缺失值；
  - DPI 下基本布局。
- XMP 使用固定 fixture 验证新建、合并、备份、原子写入和失败恢复。
- RAW+JPEG fixture 覆盖配对、孤立 RAW、孤立 JPEG、同名不同时间和跨目录情况。
- 两个推理后端均运行复核数据契约测试。
- PyInstaller 发行契约确认两版均包含 UI 与 XMP 组件，轻量版仍不包含 Torch。

### 10.2 人工验收

1. 从 1000 张项目完成导入、分析、复核和 Lightroom 导出。
2. 在 Lightroom Classic 中导入交付目录，确认星级与颜色标签正确。
3. 对已有 Lightroom XMP 的 RAW 执行原地合并，确认调整参数未丢失。
4. 在 1280×720、1440×900、4K/150% DPI 下检查布局。
5. 连续复核 100 个相似组，确认键盘操作无需鼠标即可完成。
6. 标准版与轻量版各执行一次安装、启动、分析、导出和卸载。

## 11. v0.5 完成定义

以下条件全部满足才可标记 v0.5：

- UI 与本规格确认的四项设计决策一致。
- 原 `app_qt.py` 的复核界面已按明确边界拆分，功能无回退。
- Lightroom 导出和高级原地 XMP 模式通过自动化与人工验证。
- RAW+JPEG 配对不会被误判为重复废片。
- 数据库迁移具有失败保护。
- 两个版本的完整测试、打包和安装冒烟均通过。
- 依赖与模型许可证清单和实际发行内容一致。
- 不包含调色、滤镜、云服务或直接修改 Lightroom catalog 的功能。
